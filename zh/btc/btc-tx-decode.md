# 原始交易解码（Raw Transaction Decoder）

> 粘贴已签名的 BTC 原始交易 hex，本地解出 TXID、输入输出、体积与 RBF 信号；手续费可一键联网补齐。

## 什么时候用

- 手上有一串交易 hex（钱包导出、别人发来、从节点取回），想在广播**之前**看清它到底做了什么。
- 想在广播前先算出 TXID，方便之后追踪。
- 收款方要确认这笔交易**是否可被替换**（RBF）—— 这决定了你该不该在确认前交付。
- 想知道这笔交易的费率（sat/vB），判断会不会卡在内存池里。

## 使用步骤

1. 选择**网络**。原始交易本身不携带网络标识，选错会把主网输出编成一串
   **校验和完全合法**的测试网地址 —— 请先确认。
2. 粘贴**原始交易 hex**（`0100…` 或 `0x0100…`）。解码是本地进行的，不需要联网。
3. 需要手续费时点**联网补齐** —— 见下一节。

## 输入 / 输出说明

| 项 | 含义 / 格式 |
| --- | --- |
| 网络 | 主网 / 测试网，影响地址编码 |
| 原始交易 | 已签名的交易 hex（不是 PSBT） |
| TXID | 交易哈希，可直接跳转区块浏览器 |
| 体积 | vsize（虚拟大小）· 字节数 · 权重 |
| 版本 / 时间锁 | nVersion 与 nLockTime |
| 输入 | 引用的上游输出、Sequence、见证项数量、RBF 标记 |
| 输出 | 地址、金额（BTC 与 sat）、脚本类型 |

## 手续费为什么要单独一步

**原始交易不携带输入金额。** 金额在上游 UTXO 的输出里，不在这串 hex 内 ——
所以手续费在本地**算不出来**，能本地算出的只有输出合计。

点「联网补齐」会向区块浏览器逐个查询每个输入引用的上游交易，取回金额后算出
手续费与 sat/vB 费率。**任一笔查不到就整体作废**，不会给出一个漏算的偏小值：
少算一笔输入会让手续费显示得偏小，而那个数字看起来完全正常，没有任何迹象
提示它是错的。

换一笔交易后，上次查到的金额会自动作废 —— 它不再对应当前交易。

## 注意事项 & 常见坑

- **RBF 是收款方最该看的一位。** 发出 RBF 信号（BIP-125）的交易在确认之前，
  发送方可以用更高手续费的版本替换掉，**包括替换成不给你钱的版本**。
  它藏在 `sequence` 字段里（`< 0xfffffffe` 即可替换），在一堆十六进制中肉眼看不出来，
  所以本页会单独醒目提示。作为收款方，看到 RBF 就等确认后再交付。
- **这是原始交易，不是 PSBT。** 两者格式不同：PSBT 是未完成的交易模板（带输入金额），
  原始交易是已签名的成品。粘错了会提示，请用 [PSBT 解码](./btc-psbt.md)。
- **vsize 是精确值**。交易已签名，不需要像 PSBT 那样估算，所以费率也是精确的。
- **OP_RETURN 与非标准输出没有地址**，会如实留空而不是编一个出来。
