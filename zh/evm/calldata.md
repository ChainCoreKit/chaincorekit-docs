# Calldata 编解码（Calldata Codec）

> 实时解码 / 编码交易 Input Calldata，自动识别常用函数选择器，也支持自带函数签名。

## 什么时候用

- 拿到一串 `0x` 开头的交易 Input，想还原出它调用了哪个函数、传了什么参数。
- 想按函数签名和参数手动编码出 Calldata。
- 本地词典没收录某选择器时，用自带签名解出任意 Calldata。

## 使用步骤

### 解码 Calldata

1. 在**解码 Calldata** 标签的输入框粘贴 `0x` + Calldata（示例为一笔 `transfer` 调用）。
2. 工具按前 4 字节选择器**自动比对本地词典**；命中即按签名解码。
3. 未收录时，在**规范函数签名**（可选）填入签名（如 `transfer(address,uint256)`）覆盖自动匹配。
4. 下方表格逐行列出**参数 / 参数类型 / 值**。

### 编码 Calldata

1. 切到**编码 Calldata** 标签，填入**函数签名**。
2. 在**参数**框每行填一个参数，顺序与签名一致。
3. **Calldata 结果**实时生成，点复制按钮复制。

## 输入 / 输出说明

| 项 | 含义 / 格式 |
| --- | --- |
| 输入 Calldata | `0x` + 选择器 + 参数编码 |
| 规范函数签名（解码，可选） | 覆盖自动匹配，如 `transfer(address,uint256)` |
| 解码结果 | 参数 / 参数类型 / 值 三列表格 |
| 函数签名（编码） | `name(type1,type2,…)` |
| 参数（编码） | 每行一个，顺序与签名一致 |
| Calldata 结果 | 编码后的 `0x` 数据 |

## 注意事项 & 常见坑

- **解码支持动态类型**：填入签名后可解 string / bytes / 数组等按 head-tail 偏移编码的动态类型；tuple 等复杂结构可能只按 32 字节字展示。
- **编码目前限静态类型**：支持 address / uint / bool / bytesN 等静态类型的本地编码。
- **类型别名会归一**：`uint` 视为 `uint256`、`int` 视为 `int256`、`byte` 视为 `bytes1`；归一只作用于括号内参数，不影响函数名。
- **金额是最小单位**：uint256 参数按 Wei / 代币最小单位填写，别直接填人类可读数值。
- `bytes/bytesN` 参数需 `0x` 前缀 hex；参数顺序错位会解 / 编出错误结果。
