# Token 检查器（Token Inspector）

> 读取 ERC-20 合约自报的 name / symbol / decimals / 总供应量，并标出解不出来或超出规范的字段。

## 什么时候用

- 拿到一个陌生的代币地址，想在授权或转账**之前**看清它到底是什么。
- 手上有一串原始的 uint256 余额，需要知道该除以多少才能变成人类可读的数字。
- 怀疑某个代币在伪装成知名代币（名称看起来一模一样，实则不是同一个合约）。
- 想确认某个地址在**这条链**上到底有没有合约。

## 使用步骤

1. 选择**网络**。同一个地址在不同链上未必都有合约，选错链会显示「没有合约代码」。
2. （可选）填**自定义 RPC**。留空使用公共节点；公共节点限流较紧，连续查询建议填自己的端点。
3. 粘贴**合约地址**，点**查询**。

## 输入 / 输出说明

| 项 | 含义 / 格式 |
| --- | --- |
| 网络 | 决定去哪条链上读取 |
| 自定义 RPC（可选） | 留空用公共节点 |
| 合约地址 | `0x` + 40 位十六进制，实时校验 EIP-55 |
| 名称 / 符号 | 合约的 `name()` / `symbol()` |
| 精度 decimals | 合约的 `decimals()`，金额换算的除数 |
| 总供应量 | 同时给出换算值与**最小单位原始值** |
| owner() | 该方法存在时显示，意味着合约有特权账户 |
| 代码大小 | 合约字节码长度 |

## 为什么这些字段需要「检查」

**代币元数据全部来自被查合约自身，没有一个字段天然可信。** 合约可以返回任何东西：

- **decimals 超出范围**：ERC-20 规定 `decimals` 是 `uint8`，但合约可以返回任意数。
  遇到这种值时本页**不显示换算后的数值** —— 拿一个错误的精度换算出来的数字看起来
  完全正常，却会错若干个数量级，比不显示危险得多。请以最小单位原始值为准。
- **名称含隐形字符**：零宽字符和方向覆写（RTL override）能让两个视觉上完全相同的名称
  对应不同的合约，是伪装知名代币的常见手法。命中时会明确标出。
- **bytes32 形态的名称**：MKR、SAI 等早期代币把 `name` 声明为 `bytes32` 而非 `string`。
  这是历史遗留，不是风险，会标为提示而非警告。
- **缺少方法**：不少代币没有 `owner()`，个别山寨币连 `decimals()` 都没有。
  这不算查询失败 —— 会如实标注「合约没有这个方法」。

## 注意事项 & 常见坑

- **本页不做安全评分**。同一个字段在不同项目里含义相反：有 `owner` 对一个可升级的
  稳定币是必需的，对一个自称去中心化的代币则是风险。工具只陈述合约里写着什么，
  请结合项目背景判断。
- **NFT 合约的 totalSupply 量纲不同**：它是「几个」而不是「多少钱」，也没有 decimals。
  检测到 ERC-721 / ERC-1155 接口时会提示。
- **没有合约代码有三种可能**：普通钱包地址、合约尚未部署、网络选错了。
  第三种最容易被误判成「地址抄错了」。
- **名称与符号不构成身份**。任何人都能部署一个自称 `USDC` 的合约。
  唯一的身份是**合约地址**，请对照官方渠道公布的地址核对。
