# ABI 可视化调用（ABI Console）

> 导入 ABI 自动生成函数列表，图形化读写合约；支持多合约管理，按 Read / Write 分组。

## 什么时候用

- 想像 Etherscan「Contract」页那样，不写代码就调用合约的读/写函数。
- 手上有合约 ABI（自己部署的或第三方的），需要快速交互调试。
- 需要同时管理多个合约，在它们之间切换调用。

## 使用步骤

1. 点击左侧**添加合约**，在弹窗中填写：
   - **合约名称**（如 USDC、MyToken）。
   - **区块链网络**：当前连接网络 / Ethereum / Arbitrum One / Base 等（决定区块浏览器链接与调用网络）。
   - **合约地址**（`0x…`，实时做 EIP-55 校验）。
   - **ABI 来源**：粘贴 ABI / 上传 ABI 文件（「从区块浏览器获取」「常见 ABI」为即将支持）。
2. 添加后，合约出现在左侧列表；点击选中，右侧展示函数区。
3. 用顶部分组切换 **全部 / Read / Write**（各带数量），或用**筛选函数名**输入框过滤。
4. 展开某个函数，填入参数：
   - **读函数（Read）**：填参数后调用即可看到返回值。
   - **写函数（Write）**：需连接钱包，走参数预览 → Gas 预估 → 确认 → 签名 → pending → 结果。
   - 涉及金额的参数可用右上角 **Wei / Gwei / Ether** 单位切换辅助输入。
5. 顶部操作栏可**查看 ABI**、跳**区块浏览器**、**编辑**合约，或在 `···` 菜单里**分享链接 / 删除合约**。

## 导出 / 导入合约清单

换台电脑、换个浏览器，或清理了浏览器数据，左侧这份合约列表就得一条条重录。清单可以整份带走：

左栏「添加合约」下方有一行 `合约 · N` 与一个 `···` 菜单：

| 菜单项 | 作用 |
| --- | --- |
| 导入清单 | 选择 `.json` 文件，或直接粘贴清单内容 |
| 导出全部 · N | 把当前所有合约存成一个 JSON 文件 |
| 导出当前合约 | 只导出左侧选中的那一条 |

导出的文件是标准 JSON，`abi` 字段是数组而不是字符串，可以直接喂给脚本或其它工具：

```json
{
  "format": "chaincorekit-abi-contracts",
  "version": 1,
  "exportedAt": "2026-09-16T08:30:00.000Z",
  "count": 1,
  "contracts": [
    {
      "name": "USDC",
      "network": "Ethereum",
      "address": "0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48",
      "abi": [{ "type": "function", "name": "balanceOf", "stateMutability": "view", "inputs": [], "outputs": [] }]
    }
  ]
}
```

导入**先预览、再写入**：每条都会标出将要发生什么，逐条可勾选。

| 标记 | 含义 |
| --- | --- |
| 新增 | 本地没有，会被加进列表 |
| 将跳过 / 将覆盖 | 该合约本地已有（判定口径是**同一网络上的同一地址**），具体取决于下方策略 |
| 无效 | 这条进不来，行内会写明原因：合约地址无效 / 缺少网络 / ABI 不是 JSON 数组 / 清单内重复 |

「已存在的合约」可选**跳过**（默认）或**覆盖**。导入完成后会告诉你导入了几条、覆盖了几条、跳过与无效各几条。

## 输入 / 输出说明

| 项 | 含义 / 格式 |
| --- | --- |
| 合约名称 | 自定义标识，仅用于列表展示 |
| 区块链网络 | 决定区块浏览器 URL 与调用所在链 |
| 合约地址 | `0x` + 40 位十六进制，实时 EIP-55 校验 |
| ABI 来源 | 粘贴 ABI JSON 数组 / 上传文件 |
| 单位切换 | Wei / Gwei / Ether，仅辅助金额类参数输入 |
| 函数分组 | 全部 / Read（只读）/ Write（写入） |
| 合约清单文件 | JSON，含名称 / 网络 / 地址 / ABI 四项；既收本工具导出的文件，也收一个裸数组 |

## 注意事项 & 常见坑

- **Read vs Write**：`view` / `pure` 归 Read（免费、无需签名）；`nonpayable` / `payable` 归 Write（需签名、上链）。
- **payable 函数**要额外填 ETH value；请注意单位（Wei/Gwei/Ether）。
- **金额精度**：uint256 金额按代币 `decimals` 换算（USDC=6，多数 ERC-20=18），别把原始 Wei 数当成人类可读数值。
- **参数类型**：`uint` 等价 `uint256`、`int` 等价 `int256`、`byte` 等价 `bytes1`；`bytes/bytes32` 需 `0x` 前缀 hex。
- **合约未在区块浏览器验证**时，ABI 来源不可信要留意风险，别盲目相信第三方给的 ABI。
- **同名重载函数**（如 ERC-721 的两个 `safeTransferFrom`：三参与四参）会各自显示成一张卡片，
  展开、填参、发送互不影响；发送时按你点开的那一张的参数类型编码，不会串到另一个重载上。
- **导出的清单只含合约名称、网络、地址与 ABI**，都是公开信息，不含私钥、助记词或任何凭据；
  但它仍然会暴露你在关注哪些合约、在哪条链上活动，转给别人前想一下。
- **覆盖不可撤销**：会用清单里的名称与 ABI 替换本地那条，旧的 ABI 不再保留。拿不准就先导出一份当备份。
- 合约清单保存在你自己的浏览器里，**不会同步到任何服务器**——所以换设备要靠导出 / 导入，清理浏览器数据也会一并清掉。
- 高危写函数需格外谨慎，展开时会内联提示风险，发送前还要勾选确认：
  `transferOwnership`、`renounceOwnership`、`selfdestruct`、`upgrade`，
  以及 **`setApprovalForAll`** —— 后者一次就把某个 NFT 合集的全部处置权交给对方，
  之后对方随时可以转走，而你不会再收到任何交易确认。
