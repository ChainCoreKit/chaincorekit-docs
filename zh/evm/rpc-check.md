# RPC 诊断（RPC Diagnostics）· EVM

> 在你当前的网络环境下逐个探测任意 EVM RPC 端点：能不能连、是哪条链、落后多少块、支持哪些只读能力；可以连续测多轮，看端点稳不稳。

## 什么时候用

- 某个工具一直转圈或报错，想确认是端点的问题还是别的原因。
- 手上有几个候选端点，想挑一个当前可用的。
- 需要 `debug_traceTransaction` 或历史状态，想先确认端点支不支持。
- 某个端点时好时坏，想连续测几轮看它偶发失败、限流和响应时间的波动。

## 使用步骤

1. 把 **RPC 端点**贴进来，每行一个，只接受 `http://` 或 `https://` 开头的地址。输入框下方会即时显示识别到几个端点、几个重复（只测一次）、超出 8 个上限的有几个（不会探测）；不是 http(s) 地址的行会标出行号，改正或删除后才能开始。不用事先选网络：每个端点会报出自己的 Chain ID，不同链的端点可以放在一起测。
2. 选**探测轮数**（1 / 3 / 5 / 10）。多轮时每轮依次探测所有端点，轮与轮之间间隔 3 秒。
3. 点**开始探测**。端点会**逐个串行**探测：并发只会互相拖慢，还更容易触发对端限流。
4. 想中途结束就点**停止探测**：正在测的那个端点会测完，已有结果全部保留；轮间等待中点停止会立即结束。停止后按钮旁会写明停在第几轮、完成了多少。

## 输出说明

| 列 | 含义 |
| --- | --- |
| 状态 | 可用 / 浏览器连不上 / 被限流 / 需要授权 / 应答异常；失败时下方写明原因和建议的下一步 |
| chainId | 端点实际返回的链 ID；已收录的链会附上链名，如 `8453 · Base` |
| 区块高度 | `eth_blockNumber` 结果；同一条链有多个端点时，标出比最高的落后多少块 |
| 响应时间 | 多次采样的中位数 |
| 只读能力 | `eth_call` 与历史状态（archive）的支持情况，三态：支持 / 不支持 / 未知 |

### 多轮探测的汇总

选了多轮时，结果上方先给出**按端点汇总**的一张表，每个端点一行：

| 列 | 含义 |
| --- | --- |
| 成功 / 已测 | 成功的轮数 / 已经测过的轮数；全部成功为绿色，部分成功为橙色，全部失败为红色。部分失败时端点下方会写出最近一次失败在第几轮、原因是什么 |
| chainId | 同上 |
| 最新区块 | 该端点最后一次成功时的区块高度；同一条链有多个端点时，标出比最高的落后多少块。不同链之间不比较 |
| 响应时间（中位数） | 成功轮次的中位数，下方是最小～最大值；失败轮次不计入 |
| 只读能力 | 最近一次成功那轮的结论；各轮结论不一致时会注明 |

每一轮的原始结果默认折叠，点**查看各轮明细**展开，可以按轮次筛选。同一端点反复出现的同一失败原因只在第一次写全文，之后写「原因同第 N 轮」。

在手机等窄屏上，两张表会改为每个端点一张卡片，各项结果直接列在卡片里，不用横向滑动。

## 注意事项 & 常见坑

这几条决定了你该怎么读这份结果：

- **「连不上」不等于节点挂了。** 浏览器把 CORS、DNS 解析失败、网络不通、端点不存在收敛成同一个错误，JavaScript 拿不到区别。所以这里列出的是全部可能原因，而不是替你断言某一个。
- **响应时间不是端点质量排名。** 它只反映你此刻的网络与本次采样窗口，换个地区、换个时间结论可能完全相反，也不能拿来跨端点做"谁更快"的结论。
- **历史状态探测一次成功不证明完整 Archive。** 所以结果里会写明用的是哪个区块——只有对着那个区块，结论才有意义。想确认更早的历史，需要自己用更早的区块再试。
- **「未知」不等于「不支持」。** 探测被限流、样本无效等情况都会导致判不出来，这时报的是"未知"。把未知当成不支持会让你误伤可用的端点。
- **带 API Key 的地址会被标出来。** 这类地址不要写进分享链接或未脱敏的导出文件。
