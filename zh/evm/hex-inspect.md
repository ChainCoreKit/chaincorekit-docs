# Hex 识别（Hex Inspector）

> 粘贴任意 `0x` 串，告诉你它可能是什么，并直达对应的解码工具。

## 什么时候用

- 从日志、区块浏览器、报错信息里复制到一串 `0x…`，**不知道它是什么**。
- 知道大概是 calldata，但想先确认一下再去解码。
- 想快速判断一串 32 字节的东西是交易哈希、事件 TopicID 还是存储槽值。

## 使用步骤

1. 把 `0x` 串粘贴进输入框（缺 `0x` 前缀、大小写混用都会自动容错）。
2. 结果表按「把握」从高到低列出候选，右侧是对应工具的入口。
3. 如果该串的前 4 字节命中了内置词典，会直接报出函数签名 —— 从「也许是个选择器」
   跳到「这就是 `transfer(address,uint256)`」。

## 判据说明

| 特征 | 可能是 | 去哪查 |
| --- | --- | --- |
| 4 字节 | 函数选择器 | 签名查询 |
| 20 字节 | EVM 地址 | 地址转换与 ENS |
| 32 字节 | 交易哈希 / 区块哈希 / 事件 TopicID / 存储槽值 / bytes32 文本 | 哈希工具 |
| 65 字节 | ECDSA 签名（r + s + v） | 签名验证 |
| 4 + 32n 字节 | 合约调用数据 | Calldata 解码 |
| 32 的整数倍 | ABI 编码参数 | ABI 编解码 |
| `0x60806040…` 开头 | 合约字节码 | 合约检查 |
| RLP 列表或 `0x01/02/03` 开头 | 原始交易 | 交易分析 |

## 注意事项 & 常见坑

- **这里给的是候选，不是结论。** 同一段字节在不同上下文里含义不同 ——
  32 字节既可能是交易哈希也可能是存储槽值，硬猜一个会把你带偏。
  按把握排序，点进对应工具做真正的解码。
- **32 字节可能是一把私钥。** 哈希与私钥外观完全一样。本页全程在浏览器里计算、
  不上传任何内容，但请养成习惯：**不要把私钥粘贴到任何在线工具里**。
  遇到 32 字节输入时页面会主动提醒一句。
- **本页不做解码**，只做识别与分发。要看参数、看交易内容，请走对应工具。
- **长度是最可靠的线索**，所以字节数显示在结果卡标题右侧。
