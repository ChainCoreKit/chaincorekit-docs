# 交易数据解码（Transaction Decoder）· EVM

> 把一串 `0x02f8…` 还原成字段：类型、费率、accessList、blob、授权列表，并由签名恢复发送方。覆盖 Legacy 与 EIP-2930 / 1559 / 4844 / 7702 五种类型。全部本地计算。

## 什么时候用

- 离线签好一笔交易，广播前想核对收款人、金额、nonce 有没有填错。
- 从日志或抓包里捞到一串不知道是什么的交易数据。
- 调试底层格式：交易内部就是 RLP，解不动时切到 RLP 看原始结构。

## 使用步骤

### 原始交易

1. 把 **`0x` 开头的原始已签名交易**粘进来。
2. 上方给出**交易哈希**与**由签名恢复的发送方**。
3. 下方表格逐行列出字段，随类型自动增减（`gasPrice` 只在 type 0/1 出现，`maxFeePerBlobGas` 只在 type 3，`authorizationList` 只在 type 4）。

### RLP

1. 把 `0x` 开头的 **RLP 数据**粘进来。
2. 按嵌套层级展示字节串与列表长度。

## 输入 / 输出说明

| 项 | 含义 / 格式 |
| --- | --- |
| 原始交易 | `0x` 开头的完整已签名交易 |
| 交易类型 | `0` Legacy / `1` EIP-2930 / `2` EIP-1559 / `3` EIP-4844 / `4` EIP-7702 |
| 发送方 | 由 `r`、`s`、`yParity` 反推；恢复不出来时留空 |
| RLP 数据 | `0x` 开头的十六进制 |

## 注意事项 & 常见坑

- **EIP-4844 有两种形态**：区块里存的是「交易体」，而 `eth_sendRawTransaction` 收的是 **network wrapper**（交易体 + blobs + commitments + proofs）。两者都以 `0x03` 开头，极易混淆——本工具检测到 wrapper 会明确告诉你，而不是把它的第一项当整笔交易解出一堆错字段。
- **字段数量对不上会直接报错**：少一项会让后面每个字段都读错，而且每个都「看着正常」。所以这里宁可拒绝，也不给你一份可疑的结果。
- **发送方恢复不出来时留空**：不会退而求其次给一个错地址。签名被改动过、或本就不是有效签名时会出现这种情况。
- **RLP 不带类型信息**：解出来只有嵌套的字节串。某一项到底是 `nonce` 还是 `gasPrice`，由外层结构决定——所以 RLP 视图只呈现结构，不做语义解释。
- **尾部多余字节会报错**：通常意味着输入被截断或多粘了内容，静默忽略会让你以为看到的就是全部。
