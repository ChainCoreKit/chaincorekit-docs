# 签名验证（Signature Verifier）· EVM

> 算出待签摘要、从签名恢复地址、与期望地址比对。支持 EIP-191 普通消息与 EIP-712 结构化数据。全部本地计算，不连钱包、不查链。

## 什么时候用

- 拿到一段签名，想确认它到底是不是某个地址签的。
- 合约里 `ecrecover` 出来的地址和预期对不上，想先在链下把摘要算清楚。
- 对接 EIP-712（Permit、订单签名等）时前后端哈希对不上，需要逐级排查是哪一层错了。

## 使用步骤

### 普通消息（EIP-191）

1. 填**消息原文**，上方即时给出待签摘要。
2. 贴入**签名**（`0x` 开头、65 字节），下方显示恢复出的签名者。
3. （可选）填**期望签名者地址**，工具会给出匹配 / 不匹配的判定。

### 结构化数据（EIP-712）

1. 贴入完整的 **typed data JSON**（含 `types`、`primaryType`、`domain`、`message`）。
2. 逐级给出 `encodeType` 原文、`typeHash`、`domainSeparator`、`hashStruct` 与最终 `digest`。
3. 同样可贴签名并与期望地址比对。

## 输入 / 输出说明

| 项 | 含义 / 格式 |
| --- | --- |
| 消息原文 | 任意文本，长度按 **UTF-8 字节数**计入前缀 |
| 签名 | `0x` 开头、65 字节（r ‖ s ‖ v），v 为 0/1 或 27/28 均可 |
| typed data | 标准 EIP-712 JSON；未写 `EIP712Domain` 时按 `domain` 实际字段推断 |
| digest | 最终待签摘要，即钱包实际签的那 32 字节 |

## 注意事项 & 常见坑

- **这里验的是 EOA 签名。** Safe 等合约钱包走 ERC-1271，必须调用链上 `isValidSignature` 才能验证——它们的签名在本地永远验不过，**那不代表签名无效**。
- **验签成功 ≠ 内容可信。** 签名总能恢复出「某个」地址：改一个字，恢复出的就是另一个地址，而不是报错。所以「恢复出的地址等于我期望的那个」才是有意义的结论，单看「恢复成功」没有意义。
- **EIP-712 出问题绝大多数不是密码学错误，而是 schema 对不上。** 字段顺序、类型或名字有一处与合约不同，就会算出另一个同样「看着正常」的哈希。工具给出的 `encodeType` 原文可直接与 Solidity 源码逐字符比对，比只盯着 32 字节哈希有用得多。
- **消息长度按字节计。** 含中文或 emoji 时按字符数算会得到完全不同的摘要——`中文消息` 是 4 个字符但 12 个字节。
- **依赖类型的字母序**：`encodeType` 里主类型在前、其余依赖按名称字母序排列，顺序错了 `typeHash` 就错了。
