# 批量合约读取（Batch Contract Read）· EVM

> 一次查多个合约的不同只读函数，所有调用钉在同一区块，逐项保留成功与失败。

## 什么时候用

- 要一次性拿到几十个合约的 `symbol` / `decimals` / `totalSupply` 做对账。
- 想在同一时刻横向比较多个池子或多个 Token 的状态。
- 排查时想批量调一组 view 函数，而不是逐个手点。

> 与[余额批量查询](../bulk/bulk-query-balance.md)的区别：那个是**同一个函数打多个地址**，这里是**多个合约各查各的函数**。

## 使用步骤

1. 选**网络**。
2. 每行填一条调用：

   ```
   地址  函数签名->返回类型  参数…
   ```

   例：

   ```
   0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48 symbol()->string
   0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48 balanceOf(address)->uint256 0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045
   ```

   字段用空白或逗号分隔；以 `#` 开头的行会被忽略；最多 50 条。
3. 点**查询**。结果可导出 CSV（带上区块号与网络）。

## 输入 / 输出说明

| 项 | 说明 |
| --- | --- |
| 返回类型 | 写在 `->` 之后，多个用括号包起来：`getReserves()->(uint112,uint112,uint32)` |
| 返回类型可省略 | 省了就只显示原始返回数据，**不猜它是什么类型** |
| 无法解析的行 | 会列出行号与原因，**不会静默丢弃** |
| 单项失败 | 只影响那一项，其余照常，失败数计入汇总 |

## 注意事项 & 常见坑

- **所有调用钉在同一个区块高度。** 若各条落在不同区块，你拿到的是一组「各自时刻」的快照，互相比较是错的——查余额、价格这类会变的数据时尤其致命。工具会先取一次区块号，之后所有调用都读这个高度，并把它显示出来。
- **不使用 Multicall 聚合。** 聚合确实更快，但它会把目标合约看到的 `msg.sender` 换成 Multicall 合约的地址——任何在 view 函数里读 `msg.sender` 的合约，聚合与单发的结果可能不同，**而这种差异不会报错**。所以这里逐条单发。
- **返回类型要与合约一致。** 类型写错时工具解不出来，会退回展示原始数据而不是给你一个错值。
- **只做 read。** 不发交易，不需要连钱包。
