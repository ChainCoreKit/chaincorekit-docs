# 多链助记词派生（Multi-chain Derivation）· 跨生态

> 一条 BIP39 助记词，看它在 EVM / Bitcoin / Solana / Aptos / Sui / TON 各生态下派生出什么。全部本地计算。

## 什么时候用

- 想确认某条助记词在另一条链上对应哪个地址。
- 换钱包后地址对不上，怀疑是派生路径差异。
- 想搞清楚同一条助记词为什么在 TON 里给出的地址完全不一样。

## 使用步骤

1. 粘贴助记词（或点「随机生成一条」）。输入框默认打码。
2. （可选）填 BIP39 passphrase、调整地址序号。
3. 表格逐行给出各生态的**推导路径**与地址。

## 各链规则并不通用

这是本页存在的理由。同一条助记词，各生态的处理方式差别很大：

| 生态 | 路径 / 规则 | 要注意的 |
| --- | --- | --- |
| EVM | `m/44'/60'/0'/0/i` | 标准 BIP32/44 |
| Bitcoin | `m/84'/0'/0'/0/i`（Native SegWit） | 路径前缀随地址类型变化 |
| Solana | `m/44'/501'/i'/0'` | ed25519，**只能硬化派生** |
| Aptos | `m/44'/637'/i'/0'/0'` | 地址 = `sha3_256(公钥 ‖ 0x00)`，方案字节在**后** |
| Sui | `m/44'/784'/i'/0'/0'` | 地址 = `blake2b256(0x00 ‖ 公钥)`，方案字节在**前** |
| TON | **不走 BIP39** | 见下 |

- **ed25519 系只能硬化派生。** Solana / Aptos / Sui 都是 ed25519，SLIP-0010 规定非硬化派生不成立。用普通 BIP32 会算出错的密钥。
- **Aptos 与 Sui 的方案字节位置相反。** 一个在公钥后、一个在公钥前。写反了会得到一个格式完全正确、却根本不存在的地址。
- **TON 根本不是 BIP39。** 它用 salt 为 `TON default seed` 的 PBKDF2（10 万轮），而不是 BIP39 的 seed。麻烦在于**它的词表恰好也是 BIP-39 那 2048 个词**——于是通用 BIP39 工具会把 TON 助记词照单全收、算出一把完全错误的私钥，**并且不报任何错**。反过来也一样：一条合法的 BIP39 助记词通常不是合法的 TON 助记词。本工具会分别给出两套校验结果。

## 关于 TON 地址

本工具**只给 TON 公钥，不给地址**。因为 TON 地址是 `workchain:hash(StateInit)`，而 StateInit 里含**钱包合约代码**——同一把密钥在 v3R2 / v4R2 / v5 下地址各不相同。凭空给一个地址等于误导。

## 注意事项 & 常见坑

- 地址对不上时，**先比对路径**再怀疑助记词——绝大多数情况是路径惯例不同（例如 Solana 在 Phantom 与 Ledger 下路径就不一样）。
- passphrase 会改变**除 TON 外**所有链的结果；TON 有自己的 password 机制，不共用。
- 助记词与私钥全程只在浏览器内存中，不上传、不存储、不写入 localStorage。
