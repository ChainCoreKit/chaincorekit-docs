# 交易解码（Transaction Decoder）· Solana

> 粘贴序列化后的交易，本地解出版本、签名、账户角色、指令与地址查找表引用。

## 什么时候用

- 钱包弹出签名请求，想在签之前看清这笔交易到底动了哪些账户、调了哪些程序。
- 调试自己拼的交易，确认账户顺序与 `signer` / `writable` 标记对不对。
- 拿到一段 base64 交易，想知道它是 Legacy 还是 v0、引用了哪些查找表。

## 使用步骤

1. 把交易粘进输入框，支持 **base64**、**base58** 与 **0x hex** 三种形式。
2. 结果实时显示，**全程本地解析，不发送到任何服务器**。
3. 若是 v0 且引用了地址查找表，页面会提示还有多少账户未解析，可选网络后点「拉取查找表」补全。

## 输出说明

| 区块 | 内容 |
| --- | --- |
| 概览 | 版本（Legacy / v0）、签名、消息头、`recentBlockhash` |
| 账户 | 每个账户的公钥、角色（签名者 / 可写 / 只读）、来源（消息内 / 查找表） |
| 指令 | 程序地址与已知程序名、账户下标、原始数据 |
| 地址查找表 | 表地址与它引用的可写 / 只读下标 |

## 注意事项 & 常见坑

- **v0 交易不拉查找表就是解不全的。** 消息里只存「表地址 + 下标」，真正的账户公钥在链上那张表里。只看消息里静态的那部分账户，会以为自己看到了全部参与方——而真正被动的账户可能恰恰在表里。所以未解析时页面会把「还有 N 个账户未解析」摆在显眼位置，而不是留个空格让你自行体会。
- **账户顺序是协议规定的**：静态账户 → 各表的可写项 → 各表的只读项。指令里的账户是**下标**，顺序错了就指向别的账户，所以拉取查找表后请对照下标再看一遍。
- **全零签名是占位，不是签名。** 未签名的消息被当成交易粘进来时会出现，页面会标成「占位（全零，尚未签名）」。
- **指令参数不猜。** SPL Token 的常见指令会标出名称，其余程序需要对应的 IDL 才能解出参数——认不出就只给原始字节。要解 Anchor 程序的指令请配合 [Instruction 编解码](./sol-instruction.md) 与 [Program IDL 浏览器](./sol-idl.md)。
